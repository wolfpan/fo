## 一 · 禅宗之路

### 缘起

灵山会上，世尊拈花，迦叶微笑——禅，自此教外别传、不立文字。西天二十八代传至菩提达磨，携《楞伽》四卷印心东来；二祖安心，三祖忏罪；至五祖改传《金刚经》，惠能闻「应无所住而生其心」言下大悟，得法南归，一花开五叶，禅宗自此流布天下。

本站所陈四经，正是这条路上的脚印：

| 经 | 译 | 位次 |
|---|---|---|
| 般若波罗蜜多心经 | 唐 · 玄奘（T251） | 般若心髓，二百六十言摄六百卷 |
| 金刚般若波罗蜜经 | 姚秦 · 鸠摩罗什（T235） | 五祖印心、六祖悟道之经 |
| 六祖大师法宝坛经 | 唐 · 惠能说 · 法海记（T2008） | 唯一称「经」的中国僧人言教 |
| 楞伽阿跋多罗宝经 | 刘宋 · 求那跋陀罗（T670） | 达磨印心之典，禅宗开山之源 |

建站之愿，六字而已：**传法、解悟、利生**。为此不另造「佛经网站」，只起一座**美术馆**——藏品是经，展签是注，光影是禅意；读经如观展，一步一龛，一龛一经。代码以 MIT 协议开源，经文本属公版，皆同法施——法无闭门，如一灯燃百千灯，取用无碍，明终不尽。

### 前端结构

两个页面、五个脚本，无框架、无构建链：

```
public/
├── index.html          首页 · 陈列馆（main.js 渲染）
├── sutra.html          阅读页 · 观览室（reader.js 渲染，路由 /read/:id）
├── css/style.css       全站样式：深色主题、竖排排版、展陈动效
├── js/
│   ├── main.js         首页：四经展龛渲染、造像轮换、入场显现
│   ├── reader.js       阅读页：目录抽屉、横/竖排切换、字号、进度与位置记忆
│   ├── audio.js        梵音引擎：Web Audio 实时合成五曲
│   ├── font-toggle.js  行书 ↔ 正楷 一键切换
│   └── zen.js          AI 说禅面板：点灯问曹溪影
└── assets/             造像图版、favicon 四件套
```

### 用户所见

- **首页即展馆**：犍陀罗与北魏、北齐造像十二尊随机轮换，为四经各配一龛，每次来访陈设不同；藏品编号、展签元数据（朝代、译者、章数、字数）、名句引文俱在。
- **竖排古籍阅读**：从右向左逐列展开，句读小点嵌于前字右肩，列顶对齐，卷末「止观」收尾；一键可切回横排。
- **双字体**：马善政行书（默认）↔ 霞鹜文楷正楷，一键切换、偏好记忆。
- **梵音**：晨钟、颂钵、空山、梵音、夜雨五曲，全部由浏览器实时合成，约两分半自动换曲，循环不歇。
- **阅读便利**：章节目录抽屉、字号调节、顶部进度条、位置记忆（重访回到上次读到之处）。
- **AI 说禅 · 曹溪影**：右下角点灯即问。依《坛经》蒸馏人格的流式问答，此非六祖，乃依《坛经》所塑之影；一切经文引用来自本站语料，经证卡片点击直达竖排阅读页对应章节。「参学簿」默认记下话头与要点，回访承接前问，可随时查看或一键焚去。

## 二 · 技术架构

### 总览

一句话：**Node.js + Express + 原生前端**。没有构建链、没有前端框架、经文侧没有数据库——能不引入的都不引入。

| 层 | 技术 | 用途 |
|---|---|---|
| 服务端 | Express 5（server.js，约 60 行） | 静态文件 + 两个 JSON API + 问禅路由挂载 |
| 前端 | 原生 HTML / CSS / JS | 两个页面、五个脚本，无构建 |
| 数据 | parse.cjs + data/sutras.json | 维基文库原文 → 清洗分章 → 单文件全站数据源 |
| 字体 | @fontsource + lxgw-wenkai-screen-web | 五套中文字体自托管、分片按需加载 |
| 梵音 | Web Audio API | 五曲实时合成，零音频文件 |
| AI 说禅 | SSE + Neon Postgres (pgvector) + BGE-M3 | 流式对话、混合检索、人格注入、参学簿 |

### 各层详解

**服务端**：`/api/sutras` 出经目元数据，`/api/sutra/:id` 出单经全文；页面路由仅两页。CSS/JS 按文件修改时间自动版本化（`?v=`），杜绝浏览器旧缓存；gzip 压缩对 `/api/zen/` 的 SSE 流豁免——压缩缓冲会把流式事件攒住，经 Cloudflare 回源必踩。*优势：单进程即全部，最便宜的一台 VPS 或容器即可长期运行。*

**原生前端**：两个页面五个脚本。*优势：零构建——改一行即刻生效；首屏负载极小；竖排、句读、双字体这类中文排版没有现成组件库，原生 CSS 反而最直接可控。*

**数据管线**：维基文库《大正藏》原文存于 `data/raw/`，经 `parse.cjs` 用 OpenCC 繁转简、剔除维基导语噪声、按品/分/卷分章，装配为 `data/sutras.json`。*优势：数据即文件——可 git 追踪、可 diff、离线可用；运行时无数据库，API 只是一次 JSON 读入。*

**本地分片字体**：`npm install` 时 postinstall 脚本自动把五套中文字体部署到 `public/fonts/`，浏览器按 `unicode-range` 只下载用到的字符分片。*优势：自托管、不依赖第三方 CDN；访客不必为整包中文字体（数 MB）买单。*

**梵音引擎**：振荡器、噪声源与卷积混响（2.8 秒合成脉冲响应）实时合成五曲。*优势：零音频资产、零版权问题、零下载流量，无限循环不重样。*

**AI 说禅（可选模块 `zen/`）**：

- **流式对话**走 SSE，逐字成诵；
- **混合检索**：BGE-M3 稠密向量（1024 维，存 Neon Postgres + pgvector）+ 字面精确匹配兜底，引文只认运行时检索出的【经证】段，模型不可凭记忆引经；
- **人格编译**：146KB 源调研包离线编译为常驻内核（kernel）+ 六张心智模型卡 + 机锋问答 fewshot，运行时按题检索注入，满载约 3k tokens（全量源包需 3.3–4.9 万）；
- **参学簿**：话头、画像、问答摘要存 Postgres，回访召回承接；
- 主对话模型接**任何 OpenAI 兼容端点**（百炼 / DeepSeek / GLM…），常驻内核前缀稳定、吃满 prompt 缓存。

*优势：AI 用最好的云，禅意留在本地——对话与嵌入走云端 API，检索、记忆、人格组装全在自己服务端；未配置 `zen/config.json` 时模块自动跳过，站点其余功能分毫不受影响。*

### 选型之理

这是一个内容站：正文约 8.5 万字静态数据，交互集中在排版与阅读体验。因此——

1. **依赖越少，十年后还能跑的可能性越大**：无 React/Vue、无 Webpack/Vite、无前端数据库；
2. **排版即产品**：竖排、句读、双字体、深色，CSS 原生能力胜过任何框架封装；
3. **可增量**：AI 模块整体可选，配了多一盏灯，不配是一座纯静态气质的馆。

## 三 · 快速安装

### 基础运行（约一分钟）

```bash
git clone https://github.com/wolfpan/fo.git
cd fo
npm install    # 含 postinstall：自动从 npm 包部署分片中文字体
npm start      # http://localhost:3000
```

要求 Node.js ≥ 18；端口可用环境变量 `PORT` 改。

### 启用 AI 说禅（可选）

不配置此项，站点其余功能完全正常，只是首页与阅读页右下角没有那盏灯。

```bash
# 0. 备三把钥匙：任一 OpenAI 兼容模型 API Key、Neon Postgres 连接串、阿里百炼嵌入 Key
cp zen/config.example.json zen/config.json    # 填写三处 YOUR_*（该文件已被 .gitignore 忽略）

# 1. 建库：四经分块、嵌入、灌入 Neon
node scripts/build-zen-index.cjs --dry        # 离线试跑：只分块看统计
node scripts/build-zen-index.cjs              # 正式建库（BGE-M3 嵌入 → 灌 Neon）

# 2. 在线验收
node zen/test/recall.cjs                      # golden set recall@5 ≥ 80% 为过

# 3. 重启，点灯
npm start                                     # 首页/阅读页右下角点灯即问
```

### 生产部署

任一能跑 Node 的地方皆可（VPS / 容器 / PaaS）：

```bash
PORT=3000 npm start
```

建议前置 Nginx 反代并配 HTTPS。经文侧无需任何环境变量与数据库。
